## 1. 现实校准（三个不改的事实）

1. **你还没有 C++ 工具链。** 实测：`cl`(MSVC)、`g++`、`gcc`、`clang++`、`cmake`、`ninja`、`make` 全部未安装。Week 1 唯一目标就是把它们装上并编译出一个 hello world。
2. **计时从 Week 1 重新开始。** 你已经用 Python 写过 `init` 和 `hash-object`（对象模型的概念你懂了，这是优势），但 C++ 的语法、编译、内存、调试要从零开始。不要因为"概念我都懂"而压缩 C++ 语法学习的时间。
3. **GitHub 网页登录失败大概率不是密码错。** 实测你机器：`github.com` 解析到 `20.205.243.166`，该 IP 的 443 端口**连不上**；而 `140.82.112.3 / 140.82.113.4 / 140.82.121.4`（GitHub 其他 IP）443 **能连上**，`api.github.com`、`codeload.github.com`、`gitee.com` 的 443 也**能连上**。这是链路层被阻断的特征，不是凭据错误。详见 `..\2-远程仓库与GitHub登录.md`。

## 2. 技术路线：零依赖 C++（本计划的核心改进）

| Python 原方案 | C++ 替代方案 | 工作量 | 备注 |
|---|---|---|---|
| `hashlib.sha1` | **自己实现 SHA-1** | ~120 行 | 必做，且是理解 Git 的最好练习。已知答案可验证：`"abc"` → `a9993e364706816aba3e25717850c26c9cd0d89d` |
| `zlib.compress` | **自己写 zlib "stored block"（压缩级别 0）** | ~80 行 | 关键技巧：stored block 是**合法的 DEFLATE**，所以真实 git 能正常读你写的对象。你因此完全不需要 zlib 库 |
| `zlib.decompress` | 先只解 stored block（读自己的对象） | ~50 行 | 完整 inflate（读真实 git 的对象）放到弹性周 |
| `json` 存 index | **自定 TSV 文本格式**：`mode\tsha\tpath\n` | ~60 行 | 免掉 nlohmann/json 依赖。别用二进制 index，那是 Git 里最不值得学的部分 |
| `pytest` | **自写 60 行断言宏 + `run-tests.ps1`** | ~60 行 | pytest 保留，但只用来做"对拍"（调 `mygit.exe` 和真实 `git` 比较） |
| `matplotlib` + `networkx` | C++ 输出 `.dot` 文件 → Graphviz 渲染（或 Python 读 `.mygit` 画图） | ~100 行 | Python 的 `zlib` 模块能直接解你的对象，画图很轻松 |

**副产品：你的对象库与真实 Git 二进制兼容。** 只要格式对，把 `.mygit/objects/**` 拷进任意真实仓库的 `.git/objects/`，`git cat-file -p <sha>` 就能读出来。这是本计划最强的成就感来源，也是原计划没有的验收手段。

### 对拍（差分测试）矩阵

| 编号 | 做法 | 验证了什么 | 何时可用 |
|---|---|---|---|
| O1 | `git hash-object f` 对比 `mygit hash-object f` | SHA-1 + 对象头格式 | Week 2 |
| O2 | `mygit hash-object -w f` 后 `git cat-file -p <sha>` | zlib stored block 兼容性 | Week 3 |
| O3 | 把 `.mygit/objects` 拷进临时真实仓库 → `git log` / `git cat-file -p <commit>` | tree / commit 格式 | Week 5 |
| O4 | 随机 20 步 `add/commit/branch/checkout` 后比对分支指向与文件内容 | 整体语义 | Week 7 |

> O1 即使一个字节的压缩都没写也能通过——因为 blob 的哈希只取决于未压缩内容。这是 Week 2 就能拿到的免费正反馈。

## 7. AI 使用边界（在你的版本上补充）

**可以让 AI 做**
- 解释概念（对象模型、SHA-1、deflate、C++ 语法）
- 解释编译/链接报错原文
- **写构建脚本**（`build.ps1`、`.gitignore`、VS Code `tasks.json`）——这不是你的学习目标
- 生成测试用例与边界清单
- review 你的代码、指出内存/边界问题
- 生成 README 模板、简历条目模板

**不要让 AI 做**
- 写 SHA-1、deflate、对象序列化、tree 组装、index 解析、checkout 恢复文件——**这些就是这个项目的全部价值**
- 直接给出可复制粘贴运行的完整实现
- 替你决定数据格式（它应该给你选项和取舍，由你决定）

**正确提问模板**
> "我要实现 `add <path>`：输入是相对路径，输出是更新后的 index。请只问我设计问题，不要给代码。"

**推荐反问模板（当 AI 想给你代码时）**
> "不要给代码。请列出这个函数必须处理的 5 个边界情况，以及我该怎么设计测试来发现它们。"

## 8. 远程仓库与 GitHub 登录

三条路，按顺序试：

1. **修 GitHub**：先解决链路问题（换 DNS / hosts 指向实测可通的 IP），再处理认证（**密码认证早已被 GitHub 禁用，必须用 PAT 或 SSH**）。完整诊断与步骤见 `..\2-远程仓库与GitHub登录.md`。
2. **用 Gitee**：国内 HTTPS 稳定，`git push` 用私人令牌或 SSH 都行。第 13 周的任务照做，只是换域名。
3. **本地裸仓库**（完全离线，学习价值等价）：`git init --bare F:\repos\mygit.git`，然后 `git remote add origin F:\repos\mygit.git`。`push` / `clone` / `pull` / `fetch` 的原理练得一模一样，最后再决定传到哪。

**先跑 `..\3-网络体检脚本.ps1`** 再动手，它会告诉你当前哪条路能走。

## 附录 A：三个必踩的坑（提前知道能省你一周）

1. **文本模式读文件**：`std::ifstream` 默认会把 `\r\n` 转成 `\n`，哈希必然和 git 对不上。**必须 `std::ios::binary`。** 你 Python 版已经知道用 `"rb"`，C++ 里这一点更隐蔽。
2. **SHA-1 的字节序**：消息长度和 5 个寄存器的输出都是**大端**。在 x86（小端）上直接 `memcpy` 会把哈希算错，且错得很"合理"。
3. **tree 条目排序**：目录名参与排序时要当作 `name/` 来比较，且 tree 的 mode 写 `40000`（不是 `040000`）。排序错 → tree 哈希错 → 真实 git 读不了你的提交。
